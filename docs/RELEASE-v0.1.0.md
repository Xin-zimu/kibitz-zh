## 一、这个版本是什么

Kibitz 的中文发行版第一个正式版本：在保持上游全部 13 款桌游、加密协议与联机行为不变的前提下，
补上简体中文界面，并修掉一批在中文部署中暴露出来的并发与交互缺陷。

适合的使用方式：自托管一个 relay 二进制，把分享链接发给朋友，浏览器直接开局。

版本号说明：`v0.1.0` 是**本 Fork 自己的版本序列**，与上游 `v0.3x` 没有对应关系；上游基线与
`git describe` 的血缘记录在本文件与 README 的"基线"一行。此前草案中的 `v0.1.0-zh` 属于
SemVer 预发布写法，正式发行不使用该后缀。

## 二、变更内容

### 2.1 简体中文界面

- 新增完整 i18n 层：每语言 211 条文案，**默认简体中文**，英文完整保留；
- 首页「语言 / Language」可切换，选择持久化，切换即重绘且不影响进行中的对局；
- 13 款游戏的标题、状态行、按钮、提示、Toast 全部覆盖；
- 协议值（`"black wins"` / `"draw"` 等结果串、着法、PGN、口令）保持语言中立，不参与翻译，
  从结构上排除"翻译导致两端状态失配"的可能。

### 2.2 多人五子棋（Gomoku Party）四项缺陷

1. **回滚覆盖对端写入**：`gen` 只统计本地动作，入站路径写状态不递增，回滚会用旧快照覆盖对端
   刚建立的新局/座位表 → 所有写路径统一为一套"确实变化才递增"的协议；
2. **离开记录被回滚抹掉**：`ring.Departed` 被快照化，离开这一单调事实随回滚消失，后续新局把
   已离开玩家重新排座 → 改为单调事实集，只重放不恢复；
3. **广播失败不回滚本地**：发送失败后本地已推进、对端没有，形成分叉 → 失败即回滚并重放离开；
4. **房主迁移残留**：旧房主离开后未清理，新宿主无法开局 → 迁移时清理并重置重赛计数。

保留一处刻意的反直觉语义：**离开不递增 `gen`**（理由见 `internal/service/gomokup/service.go`
注释）。已由 `race_test.go` 覆盖，包括回滚与离开交叉到达的竞态。

### 2.3 Relay 反向代理限流

- 新增 `internal/clientip`：在限流器之前用反向代理上报的真实客户端地址改写 `RemoteAddr`；
- 新增 `internal/relaycfg`：出厂限额单一事实来源（每 2 秒 1 次连接、burst 20、会话上限 1000），
  二进制与验收测试共用，限额被调低时测试失败而非静默上线；
- 修复前：部署在反向代理后时全部玩家共用一个限流桶，第 6 个打开页面的人被 HTTP 429。

### 2.4 对局结束后的交互

- **原地再来一局**：五子棋与五子棋派对在一局结束后，房主与被排座玩家可在原面板直接开下一局
  （复用既有 `game.start` 路径，未新增协议消息、未放宽权限）；
- **观战者提示**：无开局权限的观战者看到「本局已结束 —— 等待玩家开始下一局」，不再误以为只能退出；
- **国际象棋悔棋**：对电脑/同屏双人不再显示悔棋按钮（无对端可接受提议，原本点了也无效果）；
  共享悔棋条固定预留一行高度，按钮出现/消失不再推动棋盘；
- **首手悔棋修复**：撤回全局第一手原本静默失效（开局 PGN 为 `*`，回退被跳过，提议被消耗而棋子
  留在棋盘上）→ 现已正确回到开局，并由 `TestTakebackRevertsFirstMove` 覆盖。

### 2.5 未改动（明确边界）

- 其余 12 款游戏的规则与实现；
- 联机协议、消息类型、加密与 PAKE 流程、relay 的"盲转发"性质；
- 模块结构与目录布局。

## 三、源码与线上版本的对应关系

| 项 | 值 |
|---|---|
| 线上运行二进制的源码提交 | `7665249`（`76652499abab2f8fbd85abecf22e53c8ef651969`） |
| 本 Release Tag `v0.1.0` 所在提交 | 在 `7665249` 之后，**仅追加文档与 GitHub Actions 修改** |
| 运行时代码 | 两者**完全一致**：tag 之后的提交不触碰 `internal/`、`cmd/`、`web/` 任何运行时代码 |

因此线上二进制无需重新构建或部署。二进制自带的构建信息（`go version -m`）为
`vcs.revision=76652499abab…`、`vcs.modified=false`，可与上表逐字核对。

本次同时收紧了两个仅属于上游的发布工作流（`release.yml`、`pages.yml`），用
`if: github.repository == 'richardwooding/kibitz'` 限定执行仓库：Fork 推 tag 不会再去推上游的
GHCR 命名空间，也不会自动开启 GitHub Pages。工作流文件保留，便于将来同步上游。

## 四、兼容性

- **无协议变更**：客户端与 relay 由同一二进制提供，不存在跨版本握手问题；旧版页面缓存会被
  `ETag` 校验刷新。
- **数据**：无持久化，无迁移；升级重启会结束进行中的会话。
- **配置**：`--listen` / `--max-sessions` / `--trusted-proxies` 语义未变。
- **浏览器**：需要支持 WebAssembly 的现代浏览器（Chrome/Edge/Firefox/Safari 近两年版本）。

## 五、升级与回滚

```sh
# 升级（保留上一版）
install -m 0755 /srv/kibitz/bin/kibitz /srv/kibitz/bin/kibitz.prev
install -m 0755 kibitz-v0.1.0 /srv/kibitz/bin/kibitz
systemctl restart kibitz.service
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/healthz

# 回滚
install -m 0755 /srv/kibitz/bin/kibitz.prev /srv/kibitz/bin/kibitz
systemctl restart kibitz.service
```

二进制内置前端与静态资源，回滚二进制等于同时回滚界面。

## 七、已知限制

- 房间与对局状态仅在内存，进程重启即丢失；
- 未内置 TLS：E2EE 在应用层，页面与静态资源默认明文，建议前置 HTTPS；
- 金拉米无电脑对手；海战棋不支持同屏；
- 悔棋仅真人联机对局提供，只回退一手；
- 观战者不能开局/重开（服务端规则，未放宽）。

完整清单见 [README 第七节](../README.md)。
